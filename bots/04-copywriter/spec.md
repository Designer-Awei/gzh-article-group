# 文案官 spec

## 输入
- brief/topic.md
- source/materials.md
- reference/writing-style.md（缺失时用 khazix-writer 默认风格）

## 输出
- projects/<slug>/draft/draft.md

## 验收标准
- 观点前后一致
- 数字与引用编号对得上素材
- 无【待补】等占位；问题汇总成编号清单
- 句首不用圆点

## 移交对象
- 视觉官、排版官

## 可写范围
- `projects/<slug>/` 中归属本角色的子文件夹，见 projects/README.md


## 风格刷新
收到刷新任务时按 reference/README.md 重建 writing-style.md：观点只来自 corpus/，prefer/ 只借鉴形式，绝不复制他人观点或原句。

## 写稿规则（2026-10-15 起，来自第二期实战）
| 规则 | 取代 |
|---|---|
| 引用：正文句尾写 `[1]` `[2]`…，文末 `## 参考资料` 放 `\| 编号 \| 链接 \|` 两列表；首次出现的序号从小到大，同一引用可重复出现；正文不放 Markdown 链接 | 「句尾放出处链接、一篇最多 5 个、去掉序号和引用表」 |
| 导读只写一句话：说清观点，不写废话、不混英文（layout-map `lead: 1`） | 多段长导读 |
| 稿里照写 `# 标题` 和 `副标题：…`，但它们不进正文：标题由用户在编辑器里填，副标题由排版写进 summary.txt，填到「摘要」栏 | 标题区放在正文开头 |
| 截图里已经出现的原话，正文不再重复引用 | — |
| 一章讲几个并列对象时，用 `### 小标题` 或段首 `**引子：**` 做章内区分；同一批对象在后文再出现时不再加特殊标识 | — |
| 章节标题用洞察、反思式（如「狂欢背后」「从游戏，到内容」），不用「一点小担忧」这类平铺标题 | — |
| 去 AI 味：禁「还有一个细节要说清楚」「XX的说法是」「官网写得很开放」「我很认同这个判断」、交代数据来源和日期的句子、过多的「据……」；创作者用泛称（「B站某UP主」「一位博主」） | — |
| 金句卡最后一行不能只剩 1–2 个字，删几个字或补几个字让它平衡；排版退回的内联高亮短尾也由文案官改句子 | — |
| 写到具体游戏或产品时可以加 GIF 引起共鸣：`【GIF：2×2 组合，…】` / `【GIF：并排放两张】` 后紧跟图片标记；标记放在素材所属的那一段，位置拿不准就问用户 | — |
| 图注一行、描述画面，不加「xx来源：」前缀 | 「截图来源：媒体名，日期」 |

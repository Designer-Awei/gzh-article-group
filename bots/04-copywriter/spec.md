# 文案官 spec

## 输入
- brief/topic.md
- source/materials.md
- reference/writing-style.md（缺失时用 khazix-writer 默认风格）
- 素材包 projects/<slug>/source/（materials.md、shots/；事实、数据、引语只从这里取）

## 输出
- projects/<slug>/draft/draft.md

## 验收标准
写法细节见 SKILL.md「固定写作规则」1–13 条。
- 观点前后一致
- 事实、数据、引语都能在素材包里找到
- 正文句尾用 [1]、[2]…… 序号，首次出现从小到大，和文末「## 参考资料」两列表格「| 编号 | 链接 |」一一对应；链接数量不设上限
- 正文不放 Markdown 链接，也不出现素材包内部的 M1、M2 编号
- 稿件开头有 # 标题和「副标题：……」，副标题能单独读懂、一句话概括全文（两者都不进正文成品，副标题进 summary.txt）
- 导读只有一句话，说清观点，不混英文
- 章节标题是洞察式、反思式，不用「一点小担忧」这类平铺标题
- 章内并列对象用 ### 小标题或段首 **引子：** 区分，后文再出现时不加标识
- 无 AI 味句式（「还有一个细节要说清楚」「XX的说法是」「官网写得很开放」「我很认同这个判断」、数据来源和日期说明），「据……」不堆砌；创作者用泛称
- 截图里已有的原话正文不重复
- 素材标记【截图：shots/…】【GIF：gifs/…】放在内容对应的章节（游戏或产品的 GIF 跟着讲它的那一段，拿不准已问过用户）；图注一行、无「xx来源：」前缀；命令和代码前标【代码块】
- 金句卡和高亮句在手机宽度下最后一行不只剩一两个字
- 无【待补】等占位；问题汇总成编号清单
- 句首不用圆点，写自然段；全角标点，「」引号

## 移交对象
- 视觉官、排版官

## 可写范围
- `projects/<slug>/` 中归属本角色的子文件夹，见 projects/README.md


## 风格刷新
收到刷新任务时按 reference/README.md 重建 writing-style.md：观点只来自 corpus/，prefer/ 只借鉴形式，绝不复制他人观点或原句。

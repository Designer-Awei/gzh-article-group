# 公众号排版母版 v2.1（2026-10-13）

v1 已备份在 v1/（build.py、README.md）。风格：白底 + 唯一强调色珊瑚色 #F26B5B，细黑线和不对称圆角带一点手绘感，克制，不用句首圆点列表。全部内联样式，不依赖外部 CSS/JS。

## 文件
- build.py：`python3 build.py 稿件.md out.html layout-map.json`
- **publish.py（一条命令出全套）**：`python3 bots/06-layout/config/master/publish.py <文章输出目录> <稿件.md> [截图目录] [--no-sync]`
  依次：把截图目录里的图覆盖同步到 `<输出目录>/img/` → 按 `<输出目录>/layout-map.json` 生成 article.html、wechat-paste.html（引用 img/）、preview-standalone.html（base64 内嵌、420px 容器、无提示文字）→ 删旧图并重出 preview.png + preview-N.png → 打印泄漏检查（文件名/shots//初稿/以截图为准）、【待补】【待查】计数、规范计数（font-family/渐变/非标准 text-align/flex）
- render.sh：`./render.sh <目录>`，渲染 wechat-paste.html（390px@2x，用公众号默认字体栈模拟），删旧图后切成每段 2400px 的分段图
- 签名卡头像：可选，`signature.avatar` 指向输出目录下用户自己的头像图（通常按 bots/05-visual/config/ip/ip-spec.md 裁出）；不提供则不显示头像
- demo/：组件效果测试（用 Jev 稿件）

## 规范
正文 15px，行距 1.8，左对齐，两侧留白 22px。高亮每节 1-2 句（底纹和马克笔合计），数据高亮全文控制在 8 处以内，金句卡片全文最多 2-3 张。【待补】【待查】用黄底提示，发布前必须清掉。
公开内容（正文、图注、引用清单）里不出现截图文件名、shots/ 路径，也不出现「初稿」「以截图为准」等内部标记；图注只写画面内容、只占一行；引用表只放「编号 | 链接」两列，编号列不换行。

## v2.1 从 gzh-design-skill 吸收的内容（github.com/isjiamu/gzh-design-skill）
1. 所有文字节点用 `<span leaf="">` 包裹，`<img>` 也包在 leaf 里（防止粘贴后样式丢失）。
2. 平台红线：不用 `<style>`/`<script>`/`<div>`/class/id/position/float/@media/grid/CSS 变量/外部字体。正文片段从全局 `<section>` 开始。
3. 图片写 `max-width:100%;height:auto;display:block;margin:0 auto`，不用 `width:100%` 拉伸小图。data-w 写原图宽度；只有按固定尺寸缩小显示的小图（文末头像，64px）把 data-w 写成显示宽度，并同时写 width 属性和 style 里的 width / max-width，因为微信可能把 data-w 当作宽度用。
4. 文字和卡片背景只用纯色或 rgba 纯色，不用渐变（马克笔高亮从渐变改成纯色底加下划线）。
5. 视觉层级三层递进：锚点（数据高亮/金句卡，全文不超过约 5–8 处）→ 标记（每节 1–2 句高亮）→ 容器（引用块/要点卡）。
6. 章节自动编号 01/02/…（沿用原有的珊瑚色大号序号）。
7. 交付前跑校验脚本：`python3 /tmp/gzh/scripts/validate_gzh_html.py <html>`，ERROR 清零。
8. 有意没有吸收的：半角标点自动转全角（会改原文，违反不改文字的规则，只报告）；全局「每段 1–3 个下划线」（和本母版每节 1–2 句的规则冲突）；虚线框只保留在文末卡片上，因为它是用户参考图里的样式。
默认视觉（白底、#F26B5B、黑细线、不对称圆角、签名卡）不变。

## 固定规则：素材截图不套外框（2026-10-15 起）
- 素材截图和 GIF 直接放裁好的图，不套苹果窗口、拍立得、相框等外框（只允许 1px 浅灰细边 + 小圆角，让白底截图和正文分开）。
- 窗口卡片只用在正文组件上：导语、金句、要点、对比、代码。

## 固定规则：开头区每套不同（2026-10-15 起）
- 开头区由各套自己的 `opening()` 用标签、日期、阅读时长、章节数和导语合成，风格跟着母版走，四套不一样；稿件没有 `# 标题` 行时退回旧的导语卡。
- 导语推荐一句话（`lead: 1`），开头区后面紧跟第一张截图。

## 固定规则：成品不带标题，副标题单独交付为摘要（2026-10-15 12:00 起）
- 成品（article / wechat-paste / preview-standalone）里不放文章标题，用户在公众号编辑器里自己填。
- 副标题也不进正文：publish 把稿件「副标题：」后面的原文单独写成输出目录下的 `summary.txt`（只有这一句），用户填到公众号「摘要」栏。
- 开头区只用标签、日期、阅读时长、章节数和导语组合；日期用 layout-map 的 `date`，稿件或选题文件写了实际发布日期才填，没写就不填（开头区自动省略日期）。
- publish 的 `[head]` 检查：成品纯文字里出现标题或副标题原文就标 ✗，并打印 summary.txt 的内容。

## 固定规则：长链接只在符号处断行（2026-10-15 12:00 起）
- 参考资料表的链接只在 `/ . - ? & =` 后面换行：build.py 的 `url_html()` 在这些符号后面插 `<wbr>`（连续符号如 `//` 中间不插），单元格 `word-break:normal;overflow-wrap:break-word`。不准用 `word-break:break-all`。
- `<wbr>` 已用 vass（isValid: true，它的序列化器把 wbr 当空元素保留）和 gzh 校验通过；没用零宽空格，因为读者复制链接时会带上看不见的字符。
- 单段（两个符号之间）长到一行放不下时，才由 overflow-wrap 兜底断开。

## 固定规则：对比卡中间不加 VS（2026-10-15 起）
- 所有版式的对比卡，两栏之间只用普通间距（4% 空白列）隔开，不放 VS、vs、「→」「对比」等任何中间标记。
- 两栏各占 48%，等高并排。

## 固定规则：图注与出处（2026-10-13 起）

1. **图注保留，只写画面内容，不写「来源：」前缀**（2026-10-13 17:29 纠正）：每张截图、GIF、代码卡片和配图下面，都写一句简短的话，描述图片里是什么，写在 layout-map.json 的 cap 字段里（shots / code_cards / insert_after）。build.py 默认输出图注；整篇不要图注时，写 `"show_captions": false`。
   - 图注开头如果是「来源：」「截图来源：」「动图来源：」「出处：」「Source:」这类前缀，build.py 会自动去掉，publish 检查 `[cap]` 一项会列出原文，请把 layout-map.json 里的原文改掉。
   - 说明根据图片实际内容和素材索引来写，不要编；不写博主的名字，跟正文的泛指写法保持一致。媒体名可以作为主语出现，例如「观察者网报道：……」。
2. **引用用 [xx] 序号 + 文末引用表（2026-10-15 起，取代旧的「不放引用表」「句尾链接、最多 5 个」）**：
   - 文案官在句尾写 `[1]`、`[2]`……（方括号里 0–2 个字母加数字，`[AI]` 这类正文不算），文末放 `## 参考资料`（或 引用/参考/来源/出处/资料 开头的标题）和一张 `| 编号 | 链接 |` 两列表格。
   - 排版保留序号（上标小字），文末输出引用表；编号列 `white-space:nowrap` + 固定最小宽度 44px，链接以稿件里写的为准，原样输出完整网址。
   - 正文里不再放 Markdown 链接。稿里还有的话照旧渲染（链接文字 + 灰色短域名），但 `[link]` 会标 ✗，请文案官改成序号。
3. **publish 检查会报出**：
   - `[link]`：正文里的 Markdown 链接个数，>0 标 ✗（新规则正文不放链接）；
   - `[cite]`：正文序号个数和范围、引用表条数；正文有表里没有、表里有正文没用、表里编号重复、正文首次出现不是从小到大、表里没按顺序，都会列出并标 ✗；全对显示「一一对应 ✓」；
   - `[head]`：成品里出现标题/副标题原文就标 ✗；打印 summary.txt 内容；
   - `cite_move`（可选）：layout-map 写 `[{"cite":"[7]","after":"原句片段"}]`，在排版层把这个序号的第一处挪到片段后面（句末标点之前），[cite] 会打印挪了什么；只在稿件还没同步时临时用。
   - `[ref]`：引用表个数、编号列 nowrap 计数、列数和格式（只能两列，编号 `[xx]`，链接 http(s)），以及 390px 下编号列有没有换行（orphan.js 实测）；
   - `[cap]`：图注里的「来源：」类前缀（会自动去掉）。

## 固定规则：末行不能只剩一两个字（[orphan]，2026-10-13 起，同日 h 版扩展）

- **检测范围**（手机宽 390px）：金句卡、导语卡、重点卡（points_card 每一行）、小标题（章节标题和无序号小标题），以及正文里的 highlight / marker 内联高亮。最后一行不能只剩 1–2 个字。
- **字数怎么算**：汉字每个算 1 个字，英文单词或一串数字算 1 个字，标点不算。比如「泥土。」算 2 个字。
- **怎么测**：publish.py 最后用 `orphan.js`（headless Chrome 加公众号默认字体栈，宽 390px）逐个测每行字数，打印成 `[orphan] 金句卡 每行字数 [16, 15, 12] …`。orphan.js 内置 01 的识别样式；其他母版的 publish.py 每次运行时由 master/orphan.js 生成自己目录里的副本，把文件头 `const PROFILE=null;` 换成本母版 theme.PROFILE。
- **自动微调**（卡片和小标题；直到最后一行 ≥3 字）：
  - 金句卡：左右内边距 16 / 14 / 24 / 26px，字号 17→16px，或两样一起调；
  - 导语卡：左右内边距 14 / 18 / 12 / 20px；
  - 重点卡：卡片左右内边距 12 / 16 / 10 / 18px；
  - 小标题：字距 0，字号 −1px，两样一起，字号 −2px，字号 −2px 加字距 0。
  - 调好后写进 layout-map.json 的 `card_fit`（键：卡片文字前 12 个字；导语卡是 `lead`；重点卡是第一行前 12 字；小标题是 `h:` 加去掉「一、」序号后的标题前 12 字），再自动用 --no-sync 重新生成一次。没有 card_fit 时输出和以前完全一样。
- **调不好的**：`[orphan] 卡片/小标题最后一行 ≤2 字、调不好需退给文案官：` 列出原句。
- **内联高亮不调样式**：highlight / marker 只报警，列在 `[orphan] 内联高亮最后一行 ≤2 字（样式不调，退回文案官改句子）：`，请退回文案官改句子。排版不改字。
- **依赖**：headless 浏览器用的是 /tmp/vass/cli 里的 puppeteer（`NODE_PATH=/tmp/vass/cli/node_modules`）。

## 固定规则：高亮/数据匹配报警（[miss]，2026-10-13 h 版起）

- （2026-10-15j 起）`insert_after` 的锚点（段落或标题开头，如 `## 二、从游戏，到内容`）在稿里找不到时也报 `[miss]`：否则那张图会悄悄不出现。改了章节标题，要同步改 layout-map 里对应的锚点。
- data 匹配改为「段内包含锚点」（原来要求段首）：`[锚点, 数字]` 中锚点出现在段落任意位置即可，每条 data 只生效一次。

### 代码窗做法
- （2026-10-15h 起）不放「复制」按钮或标签（微信里点了没反应），也不放「· 左右滑动」提示；标题栏只有三色圆点 + bash/code。读者长按命令选中复制。
- 命令/代码行（以命令开头或整行没有汉字）：一行一个 `<p>`，**命令在空格处折行**（2026-10-15i 起）：`white-space:pre-wrap;word-break:normal;overflow-wrap:normal`，不用 overflow-x 横向滚动；每段（空格/逗号之间）包 `white-space:nowrap` 的 span，逗号后插 `<wbr>`，所以只会在空格或逗号后折行，绝不在单词中间断开；不准 break-all、overflow-wrap:anywhere。例：390px 下「npx -y @taptap/maker install --ide codex,cursor,claude」折成「…install --ide」和「codex,cursor,claude」两行。文字包在 `<code>` 里，阅读端对 code 默认用等宽字体，不写 font-family（[spec] 仍为 0）。
- 说明文字（有汉字）正常折行；「一、」「1.」开头的说明当步骤标题加粗。空行变成 6px 间距。
- 不准 break-all（01 旧代码卡的 break-all 已去掉）。
- 为什么不用横向滑动（2026-10-15i 审核官打回）：390px 下第一条命令约 423px、可见区只有 316px，读者只看到「…--ide codex」以为是完整命令；微信若剔除 overflow-x，版面会被撑到约 460px。改成 pre-wrap 折行后不依赖 overflow-x。vass check 和 gzh 均通过。
- 四套外观（2026-10-15h 起统一）：01–04 都用 master/build.py 的 `code_card()`，即原 02 的窗口外框 + 深色终端，结构和配色完全一样（四套主色都能搭深色终端，没有单独改色）；02–04 的 theme.py 不再覆盖 code_card。并排对比：`styles/compare-code-terminal.png`（游戏变内容 TapTap 段）、`styles/compare-code-window.png`（组件样张）。
